سند قفل نسخه: Agent OS v1 (فاز ۱)

این سند تعریف می‌کند Agent OS v1 در فاز ۱ چه چیزی است و چه چیزی نیست. هدف، حذف ابهام و جلوگیری از توسعه‌های تفسیرپذیر است.

تعریف عملیاتی Agent OS v1
Agent OS v1 یک «Control Plane حاکمیتی» است که اجرای هر اقدام را به مسیرهای مجاز، قابل ممیزی و Fail-Closed محدود می‌کند. Agent OS v1 یک Marketplace نیست و در این فاز، هیچ سازوکار «تصمیم‌گیری خودکار» را مجاز نمی‌کند.

قفل‌های غیرقابل دور زدن فاز ۱
در فاز ۱، هیچ Agent حق تصمیم نهایی ندارد. Agent فقط Recommendation تولید می‌کند. اجرای هر اقدام فقط پس از تأیید انسان انجام می‌شود. هیچ ورودی Voice یا Text مستقیماً پیام عملیاتی را publish نمی‌کند. همه مسیرها باید از Intent → نمایش به مدیر → امکان اصلاح → تأیید نهایی → Permit → Execution → Audit عبور کنند. هیچ AI پس از تأیید انسان حق veto ندارد. هر مسیر bypass باید Fail-fast و Reject شود.

مرزهای معماری
معماری Agent OS v1 به چهار لایه قفل‌شده تقسیم می‌شود: OS-Native، Infrastructure، Domain، Interaction. این لایه‌ها برای فاز ۱ غیرقابل تغییر هستند و هر توسعه جدید باید در یکی از این لایه‌ها جای‌گذاری و به قواعد آن مقید شود.

آنچه Agent OS v1 عمداً انجام نمی‌دهد
Agent OS v1 در فاز ۱ «خودکارسازی تصمیم» ندارد. Agent OS v1 «اتصال آزاد Marketplace» ندارد. Agent OS v1 «تغییر Policy بدون مسیر Change Management» ندارد. Agent OS v1 «اجرای مبهم» را مجاز نمی‌کند. هر دستور مبهم، اجرا را ممنوع می‌کند و باید به مسیر اصلاح و تأیید انسانی برگردد.

تعریف DoD برای قفل نسخه
هر سرویس Control Plane باید Fail-Closed باشد. هر پیام باید Audit Envelope معتبر داشته باشد. امضا و هویت باید قابل اعتبارسنجی باشد. Policy و Permit باید قبل از publish عملیاتی enforce شوند. Audit Sink باید stateful و پایدار باشد. Test Harness باید سناریوهای خرابکارانه و شکست را پوشش دهد. هر نقض، Release را رد می‌کند.
